# Career Impact Tracker — 实习/工作影响力周记

## ⚙️ 使用前先配置

这个 skill 需要你先填一份「工作源配置」，告诉它你有几份实习/工作、每份的信息去哪里找。复制下面的模板，填好后放在这个 SKILL.md 文件末尾（或者直接告诉 Claude 你的配置，让它每次记住）。

```
### 工作源配置

**[工作/实习 A 的名字]**（经理：[姓名，可选]）
- 会议记录来源：[例如 "10-Action/Internship/公司A/Meeting Note/*.md"；如果没有固定会议记录就写"无，跳过"]
- 日常更新来源：[例如 Daily Note 里 "💼 公司A" 开头的条目、Slack、email、微信]
- 其他数据源：[例如 Notion/Basecamp/项目管理工具的链接；没有就写"无"]
- 归属提醒：[如果这份工作的数据源里混有"系统/团队自动生成的记录"（不是你本人第一人称写的），提醒 Claude 不要把这些误当成你自己的工作——写清楚哪些来源是第一人称、可信]

**[工作/实习 B 的名字]**（如果只有一份工作就删掉这块）
- 同上结构...

**Impact-Log 保存路径**：[例如 "10-Action/Internship/公司A/Impact-Log.md"，每份工作一个文件]
```

支持 1 到 N 份并行工作，逐一处理，**不要把不同工作的产出混在一起**。

## Trigger
用户说："记录本周实习产出"、"更新 impact log"、"weekly impact tracker"、`/career-impact-tracker`，或每周固定时间（例如周五/周日）主动询问 "要不要跑一次本周 impact tracker？"

## 为什么要有这个 skill
求职季常见的一个问题是：**简历 bullet point 大多没有量化影响力**，原因往往不是不会写，而是事情发生的当下没有人把数字记下来，等到申请季再回忆已经晚了。这个 skill 把"记录"这一步提前到每周，实习/工作结束时应已经有一份现成的、按工作分类、按量化 impact 整理好的素材库，可以直接喂给 `maang-interview-prep` 或简历润色流程（如 `resume-tailor`）。

## 执行步骤

0. **先读「❓ 待回答」区块**（每份 Impact-Log 顶部，intro 之后、第一条周记录之前）：如果用户已经在某条问题下的"→ 你的回答"后面写了内容，把这个回答补进对应 CARL 故事的 Action/Result（用文字里提到的周次/日期匹配到正确的那条记录），然后把这条问题从「❓ 待回答」区块删除——不要留着重复问。没写答案的问题就留着不动，不要催促。

1. **确定本周范围**：从今天倒推到上一个周一（或用户指定的范围）。

2. **按配置逐一拉取每份工作的产出**：
   - 读该工作配置的"会议记录来源"，落在本周范围内的部分 → 提取 Decisions（已对齐的方向）和 Next steps（下一步该做什么，谁负责）
   - 读该工作配置的"日常更新来源"，本周范围内的条目
   - 如果配置了"其他数据源"（比如 Notion/Basecamp 链接），用对应工具读取本周更新的内容，按"归属提醒"里的规则判断哪些内容真的是用户本人做的
   - 如果本周某个来源没有内容（例如休会周），如实说明，不要编造

3. **转化为三种产出**（每份工作分开做）：
   - **本周完成（raw）**：客观事实清单，不夸大
   - **简历候选句**：强动词 + 做了什么 + 为什么做 / 目标 + 量化结果。例如把"跑了一个 outreach campaign"改写成"Executed LinkedIn outreach campaign across 79 prospects, achieving 32.9% connection rate, resulting in 1 qualified meeting booked"。**没有真实数字就不要编数字**——如果本周素材里没有量化结果，就照实写成"待补充量化指标"，并列出用户下次可以追问经理的具体问题
   - **CARL 故事种子**：只要出现"遇到问题→怎么解决→结果→学到什么"这个模式（哪怕只是苗头），就摘出 Context / Action / Result / Learning 四行的简短草稿。经理给的反馈、被指出的错误、赶上的 deadline，都是好素材，不要因为"看起来是负面的"就跳过——这正是 weakness/学习类故事最好的原料

4. **追加写入对应工作的 Impact-Log**（不要新建文件，追加进配置里指定的路径）：
   ```
   ## YYYY-MM-DD — Week of {周一日期}

   **经理反馈 / 对齐方向：**
   - ...

   **本周完成（raw）：**
   - ...

   **简历候选句：**
   - ...

   **CARL 故事种子：**
   - **Context:** ...
   - **Action:** ...
   - **Result:** ...
   - **Learning:** ...

   **下次需要补充：**
   - （只写"状态性"的跟进，例如"某来源本周未更新"——这类下次运行会自动重新检查的事）
   ```
   如果转化过程中出现**只有用户自己知道答案**的问题（例如"你对这个反馈的实际反应是什么"），不要写进"下次需要补充"——写进文件顶部的「❓ 待回答」区块（格式：`- [ ] **问题**` 换行 `  → 你的回答：`），这样用户想到答案时有固定地方回来打字，不用等下次跑 skill。

5. **回写今天的工作日志/笔记**（如果用户有 Daily Note 习惯）：加一行摘要 + 各份 Impact-Log 的链接。

## 用户输入答案的地方
用户如果想补充"只有自己知道"的信息，**固定去对应 Impact-Log.md 顶部的「❓ 待回答」区块**，在对应问题的"→ 你的回答"后面直接打字，随时可写，不用等 skill 运行。下次 skill 运行时会自动读取、归档、清空已回答的条目（见步骤 0）。

## 和其他 skill 的分工
- `maang-interview-prep` 是**单次**、面向具体职位/公司的完整面试准备包；这个 skill 是**持续性**的原始素材积累，两者应该衔接——真要准备面试时，`maang-interview-prep` 可以直接读 Impact-Log 当素材库，不用从头回忆
- `resume-tailor` 也会**只读**这些 Impact-Log，从里面挖掘尚未写进简历的量化候选句——不要让这两个 skill 互相覆盖对方的产出
- 本 skill 只处理配置里列出的工作/实习，不涉及其他生活面（学校课业、家教等）

## 输出确认
完成后用中文简短汇报：本周各份工作各写了几条简历候选句、几条 CARL 种子、还有什么没拿到，并附上对应 Impact-Log 文件的链接。
